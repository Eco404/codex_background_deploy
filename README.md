# Codex Background

让 Linux 上的 VS Code、Remote SSH 或 code-server 中的 Codex 插件，在关闭编辑器或断开连接后，仍可由后台服务继续执行任务。

本工具将 Codex 与编辑器连接分开管理，提供安装与旧版迁移、服务状态、崩溃重试、更新、备份和卸载。只处理你选择的插件目录，不修改客户端的全局 Codex 路径设置，因此不会把本地使用或连接其他主机的 VS Code 一并改掉。

支持 **Linux x64 / ARM64**，可使用 systemd 用户服务或容器启动入口。仓库附带预编译程序，核心运行不需要 Go、Node、Conda 或 Python；可选组件可能需要额外依赖。

## 开始使用

在**实际运行 Codex 插件的 Linux 主机或容器内**，以使用该插件的用户执行：

```bash
git clone https://github.com/Eco404/codex_background_deploy.git
cd codex_background_deploy
./install.sh
```

也可以下载整个仓库的 ZIP 并解压，进入目录后运行 `./install.sh`。不要只下载 `install.sh`；它需要同目录中的预编译程序。启动脚本会选择并校验本机架构的程序，打开管理界面，**不会立即安装**。

将这个目录放在长期保留的位置。备份、日志和下载缓存会集中存放在它的 `installer-data/` 下；容器中应选择持久化目录。

## 界面怎么用

首页会扫描实际环境，即使尚未安装，也能查看已有 Codex、旧部署和可用插件。菜单会按当前状态显示或禁用操作。

| 菜单 | 常用操作 |
|---|---|
| 部署管理 | 安装或迁移、可选组件、下载设置、更新和卸载 |
| 运行与维护 | 服务启停、诊断、修复 Codex 插件后台连接 |
| 备份与文件 | 查看和管理备份、查看日志、清理文件、关联移动后的维护目录 |

方向键或 `j/k` 移动，`Enter` / 空格选择，`Esc` 返回；页面有提示时可按 `r` 刷新。执行前会显示预览，按 `y` 才开始修改。

执行期间显示阶段、耗时和输出，并自动跟随最新内容；按 `Ctrl+C` 会请求取消并等待清理。执行结束时默认显示输出末尾和最终结果，此时可用 `PgUp/PgDn` 查看之前的输出，按 `End` 回到末尾。安装或迁移成功后，按 `Enter` / `Esc` 继续，会重新扫描环境并返回首页。

## 典型操作

### 首次部署：Linux 桌面或 Remote SSH

1. 先在目标 Linux 的 VS Code 环境中安装 Codex 插件。Remote SSH 场景应安装在远端。
2. 运行 `./install.sh`，进入 **部署管理 → 安装后台**。
3. 勾选要使用后台的插件目录。默认不选，常见位置如下；使用自定义目录时添加实际路径。
4. 选择检测到的兼容 Codex CLI，或选择“安装受管 Codex CLI”让工具安装一份。
5. 选择 **systemd 用户服务**。如果希望开机无需登录就启动、注销后继续运行，勾选 **启用 linger**；不勾选会保留系统现有设置，原本未启用时通常需登录后才启动。
6. “崩溃后自动重启（最多 5 次）”默认勾选。其他组件按需选择，默认不安装；核心无需额外安装 Node 或 Conda。
7. 选择下载源与代理，检查预览并确认。完成后返回首页，重新打开或重新加载目标 IDE，让 Codex 插件重新连接，再检查状态。

| 使用方式 | 常见插件目录 |
|---|---|
| Linux 本地 VS Code | `~/.vscode/extensions` |
| VS Code Remote SSH | `~/.vscode-server/extensions` |
| code-server | `~/.local/share/code-server/extensions` |

向导中手动填写目录时使用绝对路径，例如 `/home/alice/.vscode-server/extensions`。后台会先备份插件内置的 Codex 启动文件，再替换其启动方式；“配置完成”与“已观察到插件连接”是两个状态，后者需要插件实际连接。

### code-server 容器部署

1. 确认安装器目录、用户数据、运行目录和镜像实际执行的启动脚本目录都能持久化。默认运行目录为 `~/.local/share/codex-bg/`。
2. 如果插件库搜不到 Codex，可先进入 **部署管理 → 可选组件 → 微软官方插件源**，按预览启用后手动重启 code-server，再从插件界面安装 Codex。这个选项会切换整个插件库，仅在支持的 code-server 容器中提供。
3. 进入 **部署管理 → 安装后台**，选择 code-server 的插件目录和 Codex，后台方式选择 **容器启动入口**。
4. 如果向导要求填写 `entrypoint.d`，填写镜像启动时真正执行的目录。仅新建一个同名目录不能让容器自动执行其中的脚本。
5. 按需选择组件，确认安装，完成后让插件重新连接并检查状态。

容器重建后能否自启动取决于这些目录和启动机制是否保留；本工具无法替宿主机配置 Docker 挂载。主机或容器停止会中断任务，重建后启动服务不代表原任务能无缝续跑。

### 从旧部署迁移

1. 保留旧程序和备份，先等待 Codex 任务完成，并暂停发起新任务。
2. 在原部署用户下运行 `./install.sh`。检测到旧版时，**部署管理** 中显示 **迁移现有部署**。
3. 选择需要迁移的插件目录、Codex 和后台方式。检测到旧 CodexApp 时，按需选择 **迁移现有 CodexApp**。
4. 阅读预览中的旧服务、配置和备份检查。若提示忙碌、无法确认空闲、缺失原件或配置语法错误，先解决提示的问题，再重试。
5. 确认执行；完成后返回首页，检查后台状态，并重新打开插件验证连接。

支持识别原 `code-server-deploy`、`vscode-codex-background-deploy` 以及 Bash 统一版。迁移会切换服务，不是无中断操作；默认不会自动中断仍在运行的任务。自定义旧脚本或无法核实来源的资源可能需要人工处理，详见[迁移说明](docs/operations.md#安装迁移与维护)。

### 获取新版并更新已部署程序

使用 Git 下载的用户，在安装器目录执行：

```bash
git pull --ff-only
rm -f ./codex-bg
./install.sh
```

这里删除的只是**当前安装器目录内**自动生成的 `codex-bg` 副本，让脚本重新校验并提取新版；不要删除 `~/.local/share/codex-bg/` 中运行的程序。若 Git 提示本地有改动，先保留并处理改动，再更新。

随后进入 **部署管理 → 更新核心**，选择立即检查空闲或等待空闲后更新。仅拉取仓库不会替换正在运行的后台。由本工具安装的 Codex 可以在更新时指定版本；复用的外部 Codex 仍由其原安装方式维护。

### 添加组件或卸载

**部署管理 → 可选组件** 可以随时单独配置：

| 组件 | 用途与条件 |
|---|---|
| Node / Miniconda | 可选开发环境，优先复用已有兼容安装；独立安装可选择是否加入终端环境 |
| CodexApp | 可选 WebUI，普通 Linux 和容器均可用；需要可用的核心后台及 Node/npm |
| 微软官方插件源 | 将 code-server 的 Open VSX 切换为微软 Marketplace，仅支持的容器中提供 |
| apti / 图标替换 | 仅满足相应权限和资源条件的容器中提供 |

这些组件均默认不选。CodexApp 的密码文件路径可以留空：首次生成随机密码，已有密码则保留；界面会显示保存路径。

不再使用时，先在 **可选组件** 中处理 CodexApp 等依赖，再进入 **部署管理 → 卸载核心**。卸载会恢复插件启动文件并停止后台；复用环境、Codex 认证和会话保留。可选组件分别卸载，维护资料也不会随核心卸载自动删除。

## 日常维护

- **后台异常**：进入 **运行与维护 → 只读诊断**，再按提示处理。自动恢复最多连续尝试 5 次，耗尽后需要在服务菜单手动启动；手动停止、升级和卸载不会触发崩溃重试。
- **插件更新后无法连接**：先刷新状态，再选择 **修复 Codex 插件后台连接**。通常后台会自动检查已选择目录中的插件更新；缺少原件或备份时会暂停修改并提示。
- **查看备份或清理空间**：进入 **备份与文件**。普通清理会保留仍用于恢复的备份；强制删除会失去相应恢复能力。
- **移动安装器目录**：将整个目录连同 `installer-data/` 一起移动，然后使用“重新关联维护目录”。不要直接删除仍需用于恢复的维护资料。

关闭编辑器不会主动停止后台任务；崩溃后的重试只恢复服务可用性，不重放请求，也不保证崩溃时的任务继续执行。正在等待用户批准或交互输入的任务，仍需要重新连接后处理。

## 命令行与更多说明

在安装器目录也可以直接查看状态：

```bash
./install.sh inspect       # 环境与部署状态
./install.sh doctor        # 只读诊断
./install.sh logs          # 日志
./install.sh help          # 命令与参数
```
